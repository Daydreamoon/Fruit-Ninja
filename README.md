# Fruit-Ninja · AirFruit 隔空切水果

数字图像处理课程设计：基于 MediaPipe 姿态识别的隔空切水果体感游戏。

对着摄像头挥手，屏幕上跟随手部画出刀光，砍掉飞上来的水果，避开炸弹。
渲染 PySide6（QTimer + paintEvent，60fps 目标）· 识别 MediaPipe Tasks（Pose Landmarker lite，GPU delegate 可选、CPU 兜底）· 采集 OpenCV。

## 架构（输入与游戏分开的两层）

```
视觉线程（QThread）：摄像头 → PoseLandmarker → 手部刀刃点 → 共享状态（QMutex）
渲染主线程（60fps）：QTimer(16ms) → dt 物理 → paintEvent（背景缓存 / 水果 / 刀光 / HUD）
```

识别与渲染解耦：采样率随摄像头走（约 30Hz），渲染独立跑 60fps，刀光在两次采样之间线性插值。

## 运行（开发期）

> ⚠️ 本机虚拟环境放在 **`D:\FruitNinjaEnv`**（中文目录之外）。原因：位于 `D:\数字图像处理\...` 下的解释器会被本机安全软件拦掉摄像头（黑帧/拒绝访问），同一套包放到中文路径外即恢复正常，详见 docs/M0-环境探测报告.md 第 6 条。代码本身与本问题无关。

**最简单：双击 `run.bat`**（自动挑对解释器，后面可以跟同样的参数，如 `run.bat --selftest 30`）。

> ⚠️ **不要用 `python main.py`**。Anaconda base（`D:\Anaconda2`）里自带的旧版 `msvcp140.dll`（14.4x）就躺在 `python.exe` 旁边，Windows 优先加载它，而 Qt 6.12 需要 14.5x，于是 PySide6 报 `DLL load failed while importing QtCore: 找不到指定的程序`；何况 base 是 Python 3.13，mediapipe 根本没有 cp313 轮子。`main.py` 现在会先探测依赖，用错解释器时直接打印原因和正确命令（退出码 3），不再甩一堆 traceback。

```
# 一次性准备（在任意位置执行）
uv venv D:\FruitNinjaEnv --python <python3.12>
uv pip install -r requirements.txt --python D:\FruitNinjaEnv\Scripts\python.exe   # 必须用 uv：见 M0 报告

run.bat                                                 # 真机：摄像头 + 挥手
run.bat --mute                                          # 静音
run.bat --selftest 20                                   # 离屏回归自测（合成视觉，退出码 0=PASS）
run.bat --selftest 20 --camera-live --camera 0 --visible   # 真机链路自测（需人在镜头前挥手才有刀光）
run.bat --selftest 25 --visible --record demo/airfruit-demo.mp4
D:\FruitNinjaEnv\Scripts\python vision\probes.py --camera   # 摄像头/后端体检
```

首次运行会自动下载姿态模型到 `models/`（约 5.5 MB）。**真机模式启动需要约 10 秒**（摄像头冷启动 3~10s + 模型 1.8s），期间画面中央会提示"正在打开摄像头… 请把手举到镜头前"，就绪后提示消失、水果才开始出现。录屏请用 `--visible`：离屏模式没有字体，HUD 会渲染成豆腐块。

## 怎么玩（首次运行会校准 3 秒）

1. 双击 `run.bat`，等中央提示消失（约 10 秒）。
2. **举起双手在镜头前左右挥动 3 秒**——顶部绿字 "校准中 x.xs" 是在量你双手在画面里的活动范围，用来把你的手放大映射到整个屏幕。坐得远、手只在画面左下角也没关系，校准后会铺满全屏。
3. 看到 "校准完成 —— 现在挥手就是刀刃" 后，红色准星环就是你的指尖位置，挥手切水果，别碰炸弹。
4. 右下角有摄像头预览：**黄点=已识别的手，绿框=校准后的有效区**，手位置对不对看一眼就知道。

> ⚠️ **不要用 `--selftest` 来玩**。`--selftest` 是回归测试模式，刀刃由脚本驱动（自动演示），跟你挥手无关，画面底部会有红字横幅提醒。要玩就用 `run.bat` 不带参数。
>
> 启动时终端会打印当前模式：`模式：真机 — 摄像头 0，挥手切水果` 或 `模式：自动演示（刀刃由脚本驱动，与你的手无关）`，看一眼就不会搞混。

手不被识别时（超过 1.2 秒没有刀点），画面上会提示"没检测到手 —— 把手举到镜头前，正对摄像头"。此时先看右下角预览里有没有黄点：没有黄点=没识别到，有黄点但准星在别处=校准范围偏了，重启一次重新校准即可。

**刀刃取的是掌心**（手腕 + 食指根 + 小指根三点的中心）。系统只会把"正在用的手"当成刀：手要抬起来（手腕不低于手肘）、并且在动；搭在桌上两秒不动的那只手会自动消失，一动就回来。万一手势没被正确判断，用键盘强制指定：

| 键 | 作用 |
|---|---|
| `H` | 自动 → 只认左手 → 只认右手 → 自动（循环） |
| `1` / `2` / `3` | 直接切到 左手 / 右手 / 自动 |

当前模式常驻显示在 HUD 第三行。想看判定细节，运行前设 `AIRFRUIT_DEBUG_HANDS=1`，视觉线程会把每只手的判定原因和移动速度打到终端。
