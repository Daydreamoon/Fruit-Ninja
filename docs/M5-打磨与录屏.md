# M5 打磨 · 音效 / 录屏 / 参数调优

日期：2026-11-19 · 对应计划书 M5（打磨：参数调优 + 音效 + 录屏）

## 1. 程序化音效 `game/audio.py`

不引入任何音频素材：5 个音效在启动时用 numpy 合成 16-bit PCM、写入临时 WAV，
再用 `QSoundEffect` 播放，全部可失败降级。

| 音效 | 触发 | 合成手法 |
|---|---|---|
| `spawn` | 水果离开底部边缘 | 300→800Hz 上滑短音，0.12s |
| `splat` | 切中水果 | 170Hz 下滑 thump + 噪声爆点，0.22s |
| `boom` | 切中炸弹 | 70Hz 低频轰鸣 + 宽带噪声 + 积分棕噪，0.75s |
| `gameover` | 爆炸后 450ms | 330→220Hz 双音下行，0.9s |
| `slice` | 备用（预留挥刀风声） | 噪声一阶低通扫频 1400→380Hz，0.18s |

设计要点：

- **音频永远不是依赖**：`QtMultimedia` 缺失、WAV 写失败、`play()` 抛异常都只把
  `status` 记成 `unavailable/failed` 并静默降级，绝不影响渲染帧。
- `play()` 先 `stop()` 再 `play()`：连续切水果时不叠音、不爆音。
- 事件不直接调播放器：`GameState.events` 累加字符串，窗口在 `_tick` 里
  `_flush_audio_events()` 一次性取走——游戏逻辑保持纯逻辑、无 Qt 依赖。
- 自测模式 `muted=True` 但**仍然构建**音效库，这样 `--selftest` 会顺带验证
  QtMultimedia 后端可用性（实测 `audio=ready (5 sounds)`），又不会外放。

## 2. 录屏 `game/recorder.py`

`cv2.VideoWriter`（mp4v）写 MP4，帧源是 `widget.grab().toImage()`，每 tick 抓一帧。

- 默认关闭，`capture()` 在未 `start()` 时是空操作；编码异常会永久关闭录屏而不是在
  tick 里抛异常（同 M2 的教训：槽函数异常不打死事件循环，只会静默冻结逻辑）。
- `grab()` 会同步触发一次 `paintEvent`，若照常计数会把 paint fps 翻倍
  （实测 122.2 假数据）。窗口用 `self._grabbing` 标记这次抓帧，**不计入展示帧统计**，
  修复后 `ticks≈paints`（749/744）。
- 实测开销：录制时 tick fps 61.5 vs 不录制 62.5，可忽略。

## 3. 刀光平滑（视觉修正）

原实现每段单独用默认 **butt cap** 画笔描边，宽度 2~11px、辉光层 3 倍宽，
导到画面上一节一节像**贴着的一排梯形色块**。改为 `RoundCap + RoundJoin`、
辉光倍数 3.0→2.2 后，相邻段互相圆头重叠，视觉上是一笔连续的发光刀光
（对比见 demo 帧）。

## 4. 难度曲线（参数调优）

`game/fruits.py` 新增按回合递增的温和曲线，避免后期一直同速：

| 参数 | 值 | 效果 |
|---|---|---|
| `ROUND_SPEED_STEP` | 0.06 / 回合 | 第 8 回合初速 ×1.42 |
| `ROUND_SPEED_CAP` | 1.6 | 上限 ×1.6，不失控 |
| `ROUND_BOMB_STEP` | +0.01 / 回合（第 3 回合起） | 第 10 回合炸弹概率 0.20 |
| `ROUND_BOMB_CAP` | 0.22 | 上限，保证还能玩 |

## 5. 自测判据的时长自适应

原判据硬编码 `spawned>=6`，10s 短跑只生成 4 个水果就误报 FAIL。
改为 `spawn_needed = clamp(round(seconds/4), 2, 6)`：6s 冒烟测只需 2 个，
20s 需要 5 个，30s 起满额 6 个。

## 6. 一个坑：离屏模式没有字体

`QT_QPA_PLATFORM=offscreen` 下 `paintEvent` 里的中文 HUD 全部渲染成 **豆腐块（□□□）**，
`QFont("Microsoft YaHei")` 找不到可用字体数据库。渲染逻辑本身没问题——
`--visible` 真屏下同一帧文字完全正常。
**结论：录屏必须用 `--visible`**，离屏只用于数值回归。

## 7. 实测数据

| 场景 | 时长 | 渲染 | 视觉 | 录屏 | 结果 |
|---|---|---|---|---|---|
| 离屏 + 音效库构建 | 20s | 61.9fps | 30Hz / 9.0ms | — | PASS |
| 真屏 + 录制 | 12s | 61.1fps（paints 已修正） | 30Hz / 10.4ms | 749 帧 / 5.57MB | PASS |
| 真屏 + 录制（演示片） | 25s | 61.3fps | 30Hz / 10.2ms | 1560 帧 / 60fps / 26.0s / 11.9MB | PASS |

演示片：`python main.py --selftest 25 --visible --record demo/airfruit-demo.mp4`
（HUD 左上角可见 FPS 62.0 / frame 16.0ms / vision 30Hz，满足"双帧率可见"的验收要求）

## 8. 已知局限

- 演示片用的是**合成视觉**（脚本化双手扫掠）：摄像头自 M0 起打不开
  （设备绑定级 `Unable to BindToObject`），真机录像待硬件侧恢复后重拍。
- 录制帧率固定写 60fps，实际 tick 61.x → 播放比实时快约 2%，肉眼不可辨。
