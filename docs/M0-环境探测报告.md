## 踩坑记录（对后续里程碑有效）

1. **中文路径 + MediaPipe C++ 层**：`D:\数字图像处理\...` 含中文，MediaPipe 1.2.3 用 ANSI 打开模型文件直接 `FileNotFoundError`。**必须用 `model_asset_buffer=Path.read_bytes()` 传字节**，绕过其 C++ 文件层。M2 视觉线程沿用此法。
2. **MediaPipe 1.x delegate 参数要枚举**：`BaseOptions(delegate=...)` 传 `"GPU"` 字符串报 `'str' object has no attribute 'value'`（0.10 时代的写法）。正确写法 `mp_python.BaseOptions.Delegate.GPU / .CPU`。其余 API（`PoseLandmarkerOptions`、`RunningMode.VIDEO`、`detect_for_video`、`mp.Image`）与 0.10 兼容。
3. **本机 pip 网络病理**：pip（OpenSSL 栈）经 Clash fake-IP 隧道会无限卡死（连接 CloseWait + CPU 空转），curl（Windows TLS 栈）同链路正常。**本机装包一律用 uv**（Rust TLS 栈，实测秒装）+ 清华镜像直连。
4. OpenCV 5.1.0.95 与 4.14.0.94 在本机上摄像头表现一致；锁 4.14 是取 MediaPipe 生态最稳基线。
5. **后端选择（M2 真机复测补录）**：同一台相机 DSHOW 上限 10.4 fps、**MSMF 30.4 fps**。`vision/thread.py:_open_camera()` 因此改为 **MSMF 优先、DSHOW 兜底**，并用 `FIRST_FRAME_TIMEOUT_S = 1.5` 判断"打开了但不出帧"的后端，超时即换下一个。
6. **venv 路径规则（本机特有）**：位于 `D:\数字图像处理\...` 下的解释器（项目 `.venv` 及在其下新建的任何 venv）打开摄像头一律 `E_ACCESSDENIED` 或黑帧 1fps；同一套包换到 `D:\FruitNinjaEnv` 后正常 30fps。系统 python（`D:\Python\python.exe`）与 Chrome、系统相机 App 也正常。判定为本机安全软件（火绒 `HipsDaemon` 服务 + `hrdevmon` 摄像头类过滤驱动）对"未信任路径程序"的静默拒绝：该服务注册为 Auto 自启、不接受 STOP 控制码（`sc stop` 返回 1052），退出托盘 UI 也不影响它运行。**结论：代码留在中文课程目录，虚拟环境放 `D:\FruitNinjaEnv`**（不改一行代码即可绕过）；若要彻底解决需在火绒中把 `python.exe` 加入信任区或卸载火绒。
7. **黑帧陷阱**：摄像头被其它程序（系统相机 App / Chrome）占用时，OpenCV 往往**不报错**，而是返回纯黑 1fps 假流（`frame.mean()==0.0`，帧间隔 ~1000ms）。`probes.py --camera` 因此增加了亮度与 `[OK|SLOW|BLACK-fake-stream]` 判定，避免把"能打开"误判成"能用"。

## 摄像头排查全链路（已解决，留档）

现象：设备管理器正常（ProblemCode 0，驱动 `usbvideo.inf`，实例 `USB\VID_2B7E&PID_B651&MI_00`）→ 相机隐私授权 HKCU/HKLM 均 Allow → 无组策略/MDM 限制 → pygrabber 可枚举 `['HD Webcam']` → 但 OpenCV 各后端打不开，ffmpeg dshow 报 `Unable to BindToObject`，pygrabber `BindToObject` 抛 `0x80070005 E_ACCESSDENIED`（同一时刻音频设备绑定正常，说明不是通用权限问题）。

决定性对照实验：

- 系统相机 App / Chrome 调用同一摄像头 → **画面正常**，说明硬件、驱动、Windows 隐私设置全部正常；
- 换到工作区外的解释器 → **画面正常，30.4 fps**；工作区内任何解释器 → 拒绝或黑帧；
- 摄像头设备类 `{ca3e7ab9-b4c3-4ae6-8251-579ef933890f}` 的 `UpperFilters = hrdevmon,ksthunk`，`hrdevmon` 状态 Running、`StartMode=Boot`。

结论：拦截发生在"打开摄像头设备"这一层，按可执行文件路径放行/拒绝。改用工作区外的 venv 后完全恢复正常。
