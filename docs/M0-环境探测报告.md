## 踩坑记录（对后续里程碑有效）

1. **中文路径 + MediaPipe C++ 层**：`D:\数字图像处理\...` 含中文，MediaPipe 1.2.3 用 ANSI 打开模型文件直接 `FileNotFoundError`。**必须用 `model_asset_buffer=Path.read_bytes()` 传字节**，绕过其 C++ 文件层。M2 视觉线程沿用此法。
2. **MediaPipe 1.x delegate 参数要枚举**：`BaseOptions(delegate=...)` 传 `"GPU"` 字符串报 `'str' object has no attribute 'value'`（0.10 时代的写法）。正确写法 `mp_python.BaseOptions.Delegate.GPU / .CPU`。其余 API（`PoseLandmarkerOptions`、`RunningMode.VIDEO`、`detect_for_video`、`mp.Image`）与 0.10 兼容。
3. **本机 pip 网络病理**：pip（OpenSSL 栈）经 Clash fake-IP 隧道会无限卡死（连接 CloseWait + CPU 空转），curl（Windows TLS 栈）同链路正常。**本机装包一律用 uv**（Rust TLS 栈，实测秒装）+ 清华镜像直连。
4. OpenCV 5.1.0.95 与 4.14.0.94 在本机上摄像头表现一致（都打不开，原因在设备绑定层，与 OpenCV 版本无关）；锁 4.14 是取 MediaPipe 生态最稳基线。

## 摄像头异常详情（证据链）

设备管理器正常（ProblemCode 0，驱动 10.0.26100.9444，实例 `USB\VID_2B7E&PID_B651&MI_00`）→ 相机隐私授权 HKCU/HKLM 均 Allow → consent store 无进程在用（微信/B站/浏览器历史使用均已 Stop）→ pygrabber（纯 DirectShow COM）可枚举 `['HD Webcam']` → 但：

- OpenCV 4.14 / 5.1，DSHOW / MSMF / ANY 三后端 × index 0~2，全部打开失败；
- ffmpeg dshow：`Unable to BindToObject for HD Webcam` / `Could not find video device with name [HD Webcam]`。

判定：设备枚举可见、**绑定/起流失败**，典型设备状态卡死。`pnputil /restart-device` 需管理员（当前 shell 未提权，Access denied）。

**用户侧恢复手段（任选其一）**：拔插 USB / Fn 摄像头键 / 设备管理器禁用再启用 / 重启电脑。恢复后执行 `python vision/probes.py --camera` 补测实测帧率（默认设置 vs MJPG+60fps 请求各 4 秒）。

## 对后续里程碑的影响

- M1 渲染骨架：**无影响**（纯 Qt，不碰摄像头）。
- M2 视觉接入：依赖摄像头恢复；CPU 推理 8.6ms/帧已证明算力富余极大（即使 60Hz 采样也只占 52% 单核）。
- 采样率指标：CPU 侧无瓶颈，最终采样率将取决于摄像头恢复后的实测帧率（预期笔记本/外接 UVC 常见为 30fps，满足计划书 ≥30Hz）。
