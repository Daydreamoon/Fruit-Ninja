# M6 交互反馈与自动校准

## 起因

试玩反馈（原话）：

> 这个程序根本没有完成，我的手势根本没有履行，只是程序它在自动切，我根本不知道我手指指的位置在哪。

拆开是两件事，都不是识别坏了：

1. **"程序自己在切"** —— 试玩时用的是 `--selftest`（回归测试模式），这个模式下视觉走合成源，刀刃由脚本驱动自动追水果切片。功能上是故意的，但界面上没有任何区分，用户自然理解成"程序在自动切"。
2. **"不知道手指在哪"** —— 真机模式下：准星只有 24px，太小；屏幕上看不到摄像头画面，无法建立"我的手在哪 ↔ 屏幕哪里"的对应；摄像头冷启动约 10 秒只有一行小字提示；另外手垂在画面下半部时，手在屏幕上只能到屏幕下半区，怎么挥都够不到上面的水果。

## 改动

### 1. 模式不再靠猜

- 终端启动即打印：`[AirFruit] 模式：真机 — 摄像头 0，挥手切水果` 或 `[AirFruit] 模式：自动演示（刀刃由脚本驱动，与你的手无关）`。
- 自动演示模式画面底部常驻红色横幅：`自动演示模式：刀刃由脚本驱动，与你的手无关（不加 --selftest 就是真机模式）`。
- 自动演示模式的刀刃改为**主动追最靠下的非炸弹水果**（`DEMO_BLADE_SPEED = 4200 px/s` 限速 + 无果时正弦扫掠）。原来的固定扫掠路线和随机水果位置重叠不稳定，10 秒自测出现过 `sliced=0` 的随机 FAIL；改成追果后 8 秒跑出 `spawned=8 sliced=6 missed=0`。

### 2. 自动校准（核心）

3 秒采集双手在**原始相机坐标**里的 min/max，加边距（`CALIB_PAD = 0.06`）后把这个矩形映射到整块屏幕：

```
x0,x1 = _widen(min(xs) - pad, max(xs) + pad, CALIB_MIN_BOX)   # 同理 y
屏幕坐标 = clamp((相机坐标 - 框起点) / 框尺寸)
```

- 关键常量：`CALIB_SECONDS = 3.0`、`CALIB_MIN_SPAN = 0.10`（运动幅度小于此值就判定"没动"，退回默认框）、`CALIB_MIN_BOX = 0.50`（框太小则以中心撑到 0.5，避免只用一只手校准把另一只手顶到屏幕边缘）、`CALIB_DEFAULT = (0.10, 0.90, 0.06, 0.94)`。
- 实测日志：`[calib] hands move in x 0.00..0.50, y 0.50..1.00 (376 samples)` —— 试玩者坐在画面左下角、手只在左下四分之一活动，校准后同样的小动作就能覆盖全屏。
- 识别层（`vision/thread.py`）不再做任何 ROI 映射，只发布**原始镜像相机坐标**；映射全部在渲染层，`VISIBILITY_MIN` 从 0.5 降到 0.35（手挥动时可见度经常掉到 0.5 以下，漏采即刀光断裂）。

### 3. 看得见的反馈

- 准星：24px 小圆 → **半径 30 的脉冲环** + 中心实心点 + 四向刻度 + "手1/手2"标签。
- 右下角摄像头预览放大到 360×202，叠加**黄点（已识别的手，相机坐标）**与**绿色虚线校准框**，标题写明"黄点=已识别的手（绿框=校准后的有效区）"。
- 启动阶段：`正在加载姿态模型… / 正在打开摄像头… / 正在启动识别…` + `已等待 N 秒（摄像头首次打开较慢，最多约 10 秒）`；未就绪时**不再画空闲脉冲圆**（原来和提示文字重叠成一团）。
- 校准阶段：`校准中 x.xs —— 请举双手在镜头前左右挥动（决定你的手势映射范围）`，完成后 2 秒 `校准完成 —— 现在挥手就是刀刃`。
- 掉线提示：超过 1.2 秒没有刀点 → `没检测到手 —— 把手举到镜头前，正对摄像头（右下角是摄像头画面）`。

## 实测

| 场景 | 结果 |
|---|---|
| `run.bat --selftest 8 --visible --record demo/ux-synth.mp4` | 61.0fps / 30Hz / spawned=8 sliced=6 missed=0 / 红色横幅完整显示 / PASS |
| `--selftest 16 --camera-live --camera 0 --visible --record demo/ux-live.mp4` | vision ok 30~31Hz / infer 10.3~14.4ms / blades 1~2 / 校准日志正常 / PASS |
| 抽帧复核 `demo/ux-live-1050.png` | 准星环位于屏幕上中部，预览内可见真人画面 + 黄点，校准框生效 |

## 经验

- 自测模式与试玩模式必须在**画面上**区分，不能只写在命令行参数里——用户不会读参数，只会读画面。
- 手部绝对位置映射到全屏，对"坐在桌前、手在画面下半部"的玩家是致命的手感问题；**用玩家的真实活动范围做归一化**比给一堆操作说明有效得多。
- 相机坐标归一化系数（ROI）放在识别层会让视觉线程掺杂显示逻辑，挪到渲染层后 `vision/shared.py` 又能保持纯粹。
