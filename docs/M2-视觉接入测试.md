# M2 视觉接入测试记录

日期：2026-11-19 · 分支 main · 目标：视觉线程 → 共享状态 → 渲染窗口全链路打通。

## 交付物

- `vision/shared.py`：`SharedVisionState`（Lock 守护；`publish` / `publish_status` / `snapshot`，采样率滑窗 1s）；`BladePoint(x, y, visibility)` 归一化坐标、镜像已完成。
- `vision/thread.py`：`VisionThread(QThread)`，循环 = 取帧（合成/摄像头）→ 镜像 → RGB → `detect_for_video` → 刀刃点（小指/食指中点，visibility>0.5）→ 240×135 预览 → publish。
- `game/window.py`：集成共享状态，画刀点十字准星、迷你预览、HUD 增加视觉状态行。
- `main.py`：`--camera N`（真机）；`--selftest [s]`（合成视觉回归）。

## 合成自测（PASS）

```
SELFTEST seconds=12.0 ticks=750 paints=750
SELFTEST avg tick fps=62.5 avg paint fps=62.5
SELFTEST vision status=ok hz=30 samples=324 infer_ms=8.9
SELFTEST PASS (require render>=55fps, vision>=20Hz)
```

结论：视觉线程与渲染线程共存下渲染仍 62.5fps；视觉按 30Hz 源节拍精确步进（frames 均匀 30/s）；CPU 推理 8.9ms。

## 过程中发现的问题与修复

1. **Qt6 `quit()` 语义坑（自测假阴性）**：Qt6 起 `app.quit()` 先关闭所有顶层窗口 → `closeEvent` → `shutdown()` 把视觉线程先杀掉。最初在 `exec()` 返回后才采样，读到的是"尸检"数据（status=stopped、末秒滑窗空、hz=0），三跑三 FAIL，一度误判为线程崩溃。修复：采样与 PASS 判定搬进定时器槽函数，在 `app.quit()` 之前取证。真因由插桩日志定位：`loop exit stop_flag=True` 恰好出现在 quit 时刻、此前 12 秒帧数均匀。
2. **状态遮蔽**：循环尾 `publish_status("stopped")` 会覆盖异常状态，让真实错误不可见。修复：`landmark_error` / `camera_read_failed` 时不被 stopped 覆盖；单帧异常改为记日志 + 200ms 冷却 + 继续跑（不再杀线程），后续成功发布自愈为 ok。
3. **合成节拍**：合成源按 30Hz `time.sleep` 步进（对齐真实摄像头节拍，遵守计划书"采样率随源走"）；Windows sleep 粒度 ~15.6ms 在 33ms 周期下实测无碍。

## 真机复测（2026-11-19，摄像头打通后）

环境：`D:\FruitNinjaEnv`（中文路径外的 venv，成因见 M0 报告第 6 条）。

**1) 摄像头后端体检（`vision/probes.py --camera`，真实画面）**

```
[camera] MSMF 1280x720@30     measured   30.4 fps @ 1280x720  brightness 88.3  [OK]
[camera] DSHOW 1280x720@30    measured   10.4 fps @ 1280x720  brightness 98.7  [SLOW]
```

**2) 真机链路自测（`main.py --selftest 20 --camera-live --camera 0 --visible`）**

`--camera-live` 是为此新增的开关：保留定时自测，但把合成视觉换成真实摄像头（默认 `--selftest` 仍走合成，保证无摄像头也能回归）。

```
SELFTEST seconds=20.1 ticks=1250 paints=1249
SELFTEST avg tick fps=62.0 avg paint fps=62.0
SELFTEST vision status=ok hz=30 samples=288 infer_ms=8.7
SELFTEST blades_now=0 (real hands in frame)
SELFTEST trail_points=0
SELFTEST game spawned=11 sliced=0 missed=10 bombs=0 round=4 score=-54
SELFTEST PASS (render>=55fps, vision>=20Hz status=ok, spawn>=5 (live camera))
```

结论（如实记录）：

- **真实摄像头帧进入 MediaPipe 并稳定出结果**：status=ok、30Hz、推理 8.7ms（与 M0 的 116Hz 基准一致），渲染 62.0fps 与视觉共存无争抢；
- 这一轮 **blades_now=0**：测试时画面里没有手（人在桌前、手不在取景范围），所以没有刀刃点、也没有切割 —— 这是录像/走位问题，不是链路问题。**"挥手切中水果"需要真人入镜才能验证**，逻辑路径（刀刃点→刀光→点到线段碰撞→切分）已由合成自测覆盖（M3/M4）；
- 因此真机自测的 PASS 判据拆成两套：合成模式查 `trail>=3 && slice>=1`；`--camera-live` 只查管线（status=ok、≥20Hz、有水果波次），不把"手必须在镜头里"写进自动判据；
- 唯一环境约束是后端选择：**MSMF 30fps / DSHOW 10fps**，已把 `_open_camera()` 改为 MSMF 优先 + 1.5s 首帧超时兜底。
